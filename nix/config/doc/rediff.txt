HOW TO REVIEW                                                *rediff-workflow*

1. Open rediff in a Git checkout (or Space r). j/k in the tree previews files.
   Tab enters the diff. ]/[ moves between hunks; :fs/:fu switches Git groups.
2. Read red deletions and green additions. :view toggles split/merged layout.
   Press i to add/edit a note, or select lines with V then a for a range note.
3. Write the note, Esc then :w to save it locally. @ lists/searches saved notes.
4. :harness use amp connects to your local agent (see |rediff-harness| for setup).
   :w from the tree/diff sends saved notes. :hs sends a separate general message.
5. As the agent edits, files refresh. Violet ◆ means changed/unseen; cyan ◇ means
   changed/seen after 1s in the focused diff. See |rediff-git| for baseline rules.
6. Stage deliberately with s (hunk) or S (file); sending notes never stages code.
   Space R refreshes now. Space q leaves Review for ordinary editing.

REVIEW QUICK REFERENCE

  Tab                 Switch tree/diff focus
  Space e / Space d   Focus tree / diff or editor
  Space j / Space k   Next/previous changed file
  h / l in tree       Collapse/expand group (also Left/Right); restore selection
  Enter in tree       Expand group only; keep tree focus
  ] / [               Next/previous hunk within the current Git group
  :fs / :fu           Focus STAGED / UNSTAGED
  s / S               Stage/unstage hunk / whole file
  i                   Edit annotation here, or create one
  v / V / Ctrl-v, a   Annotate a character / line / block selection
  @ / :al             Search annotations and jump to one
  } / {               Next/previous annotation
  d                   Delete annotation here (source panes only)
  :w in annotation    Save note locally and close
  :w in diff/tree     Send saved annotations
  :hs                 Compose a general harness message
  Space R             Refresh files and snapshots
  :view               Toggle split/merged diff
  Space r / Space q   Toggle / leave Review

==============================================================================
REVIEW AND ANNOTATIONS                                          *rediff-review*

Interactive startup without file arguments opens Review inside Git, with tree
focus and a diff preview. File arguments open directly for editing.
Moving onto a file previews it; Tab enters the diff. Space q returns to editing.
Outside Git, startup stays in ordinary editing without a sidebar.
Headless runs open neither Review nor the tree. Space r toggles Review.
The bottom bar shows the branch (or detached @short-SHA), harness and delivery.

Source panes are protected snapshots. Editing commands open a note instead of
changing code. i edits the note under the cursor; overlapping notes open a picker.
:annotations new always creates a separate note. For an exact range, select with
v/V/Ctrl-v, then a (also i or Space c). The harness receives the selection's range
and character/block columns, not just the cursor line.

The note editor floats below the selected range without resizing the diff panes.
Notes use normal Neovim editing. Esc returns to Normal mode:
  :w / :wq    Save locally and close; never send
  :q / :q!    Discard unsaved edits and close; keep any previously saved note

Saved notes appear as orange text under their source range. Orange >> in the gutter
marks notes at the cursor. @ searches filenames and note text; Enter jumps, Esc
cancels. i edits that note. } / { cycles in creation order across files/sides;
counts work (3}). d deletes a note, not source or already-sent feedback. These
bindings leave ordinary files/note text unchanged.

Jumping to an older note shows its original snapshot and pauses refresh/staging.
Space R returns to current files. Old-side notes switch merged view to split.
Editing a note preserves its anchor. :w in diff/tree sends only saved notes;
it never writes or stages source. See |rediff-drafts| for retention and retry.

GIT AND REFRESH                                                    *rediff-git*

STAGED compares HEAD/index; UNSTAGED compares index/worktree and includes untracked
files. Badges: M modified, U untracked, R rename, A added, D deleted. Partially
staged files appear in both groups. h/Left collapses a group (▸); l/Right or Enter
expands it (▾) and restores its selected file. Enter never collapses a group.
j/k or Up/Down moves between visible files
and collapsed or empty group headers, skipping blank rows. The selected header
is highlighted. Refresh preserves collapsed groups;
:fs/:fu and hunk navigation reveal their target file.

Change awareness (automatic, for this editor session):
  Violet ◆       Changed since the last accepted send, not yet seen; pulses for 2s
  Cyan ◇         Changed since that send, already seen
  No diamond     Matches the baseline or was acknowledged by staging/unstaging
Hunks use matching labels and line-number colors; red/green still mean delete/add.
A hunk becomes seen after 1s visible in a focused diff pane, not a tree preview.
A successful s/S clears the affected hunk indicators in either group. Moving them
back does not restore purple; new edits do. Other unread hunks stay unread.
A file stays unseen while any changed hunk is unseen. This records exposure, not
approval. The baseline starts with Review's initial contents.
Accepted local-harness sends reset the baseline to pre-send contents;
failed/local-only sends and messages to other worktrees do not. Changes are detected
on refresh regardless of who edited them. Paths no longer in Git's diff leave the
tree. Context-only line shifts do not count as new hunks. No manual marks to manage.

] / [ wraps through hunks within the current group; counts work (3]). :fs / :fu
switch groups without changing pane focus. Space j/k moves files across groups.

s in a source pane toggles its Git hunk; S toggles the selected/displayed file.
UNSTAGED stages; STAGED unstages. These actions apply immediately, change only
the index, and reject stale snapshots. Inside ordinary files/notes, s/S still
edit text. An all-green new file is one hunk: s stages it and advances to the next
unstaged hunk (or unstages it from STAGED). Empty/deleted files need S; renames
use delete/add pairs.

After staging, selection advances within the original group. Whole-file actions
use the previous file at the end; hunk actions wrap to the next remaining hunk.
An exhausted group stays empty instead of following the file into the other group.
Git may combine nearby displayed changes into one staging hunk.

Connected Amp file-edit events trigger refreshes in this worktree. Polling every
three seconds catches other edits/index changes. Refresh runs with Normal-mode
tree/diff/harness-message focus, preserves selection/focus, and pauses for
annotation editing, typing, selections, commands, pickers and delivery.
Typing in the harness send pane does not pause refresh or interrupt the draft.
Notes keep their original snapshots.
Space R / :ReviewRefresh refreshes immediately without sending feedback.
Use it instead of :bufdo e: Review panes are snapshots, not ordinary file buffers.
Outside Review, :checktime checks loaded files for external changes.

Set programs.rediff.reviewRefreshInterval in Home Manager, or add
"review_refresh_interval": 10 to settings.json in stdpath('config') (normally
~/.config/rediff). Use a whole number of seconds; 0 disables fallback polling.
Apply your Home Manager configuration, or save settings.json if not managed by
Home Manager, then leave/re-enter Review (Space q, Space r).
Amp file events and Space R still work with polling disabled.

==============================================================================
AGENT HARNESSES                                               *rediff-harness*

For a running Amp session, use :harness install amp once, then :harness connect amp.
Use :harness use amp to select Amp and connect in this worktree. Connecting sends
nothing. :hc opens the connection panel (Amp); :hl / :harness list opens the same
searchable panel for all available sessions. Each row shows its worktree directory;
long paths are shortened in the list, with the full path in the selected details.
  /           Filter by alias, provider, title, ID, worktree, or activity
  Enter       Connect/disconnect; connecting locally selects the annotation target
  s / r / d   Message / rename locally / disconnect selected harness
  c / R / q   Connected-only filter / rediscover / close

Multiple harnesses can stay connected. :hs asks which one when there is more than
one; :harness send ALIAS chooses directly. Each recipient has its own message draft:
  :w          Send; keep panel open
  :wq         Send and close
  :q / :q!    Close without sending; retain draft until editor exit

Accepted/completed delivery clears sent text, preserving newer edits. Failed,
pending and local-only messages remain drafts. In Normal mode, Tab returns to
the Review tree without closing/sending; Insert-mode Tab remains text input.
:hs takes no inline message argument. General messages never include review notes.

Annotations only go to this worktree's selected harness. General messages may go
to another worktree and include sender directory, Neovim instance, and recipient.
External recipients are instructed not to edit the sender's worktree. This is
agent policy, not a filesystem sandbox. Separate editors can watch the same agent.
Amp streams running/idle/approval/error state and active tool names to the panel.
Offline or unsupported activity is shown as such, never inferred from an ACK.
Aliases persist locally; connection subscriptions end when this editor exits.

Plugin installation asks for confirmation, preserves Home Manager symlinks, and
does not install/authenticate the Amp CLI. With a live target, it also requests
an agent-mediated reload; queued does not mean reloaded. Without one, reload Amp
manually once. Reconnect afterwards. Live install/connect supports Amp only.

CLI continuation is a separate transport; select an explicit session:
  :ReviewHarness amp T-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
  :ReviewHarness claude SESSION_ID
  :ReviewHarness custom
  :ReviewHarness none

These bindings persist per worktree. Authenticate the CLI separately and stop any
other process driving that session. This does not synchronize remote workspaces
or bypass agent permissions. Custom receivers use programs.rediff.feedbackCommand
or feedback_command in settings.json; they receive a JSON path and must acknowledge
its submission ID. See nix/README.md for installation and receiver details.

==============================================================================
WORKTREES                                                  *rediff-worktrees*

:worktree list or :worktree switch opens a chooser. Supply a branch/path to switch
directly. :harness use amp|claude selects the launch type for this worktree.

:worktree new [branch [path]] creates from current HEAD and starts that harness in
a terminal tab. Omitted branch prompts; omitted path uses a sibling directory.
The CLI must already be installed/authenticated. Existing branches/paths are never
forced. A launch failure keeps the worktree; inspect its terminal and :messages.
Ctrl-\ Ctrl-N leaves Terminal mode; gT returns to Review. Editor exit stops its
terminal processes. Switching alone never launches a harness.

New worktrees inherit launch type, not connections or drafts. Dirty files and
saved notes stay with their checkout; save/close an open note before switching.
Changing harness type disconnects incompatible bindings but retains drafts.

==============================================================================
PANES AND VIEW                                                   *rediff-view*

:view split shows old/new panes; :view merged shows deleted rows above new text.
:view toggles while retaining file/hunk and notes. Merged deletions are virtual:
use split for exact old-side selections. Old-side search/note jumps do this for you.

  Space E               Toggle filesystem tree; focus-only in Review
  Cmd-w h/j/k/l         Focus adjacent pane (macOS); Cmd-w w cycles
  gt / gT              Next/previous tab
  :setlocal [no]number  Show/hide line numbers
  :setlocal [no]wrap    Wrap/unwrap text

Cmd-w is a prefix, then a direction. Your terminal must forward Command keys;
Kitty needs `map cmd+w no_op`. Normal/Visual Ctrl-w window navigation is disabled;
Insert Ctrl-w still deletes a word. Closing a required source pane exits Review.

Additions are green, deletions red. Difftastic supplies structural token highlights;
text highlights remain on failure/timeout or files over 1 MB. Git defines staging
hunks regardless of rendering. The bottom bar names the active diff tool.

==============================================================================
ORDINARY EDITING                                              *rediff-editing*

Normal Neovim editing applies outside protected source panes. Space f searches
project files; Space / searches saved contents. In Review these search changed
entries and both snapshot sides, including deletions. Enter chooses; Esc cancels.
/ and n/N search the current buffer. ? opens this guide; use :? for backward search.

Ctrl-a / Ctrl-e moves to line start/end in Insert and command/search input.
Option+Left/Up/h/k moves a word backward; Option+Right/Down/l/j moves forward.
Set your terminal's Option key to Alt/Meta; Esc-b/Esc-f sequences also work.

For native navigation/editing, see :help motion, :help editing, :help undo,
:help registers and :help windows. File-tree actions: |neo-tree-mappings|.

COMMAND INDEX                                                *rediff-commands*

Space p / :Commands fuzzy-finds commands. Enter puts one on the command line;
add arguments and press Enter again to run. Tab accepts inline suggestions or
completes arguments; Ctrl-d lists matches. :command lists user/plugin commands.

Scripts use uppercase names below. Typed aliases: :harness = :Harness,
:hs = :Harness send, :hl = :Harness list, :hc = :Harness connect,
:ft = :Explorer, :annotations = :Annotations,
:al = :Annotations list, :worktree = :Worktree. In Review, :view = :View,
:focus = :Focus, :fs = :Focus staged, :fu = :Focus unstaged.

  :Review / :ReviewLeave       Enter/leave Review
  :Explorer / :FocusDiff       Focus tree / diff or editor
  :Files / :Search             Fuzzy file / text search
  :Commands                   Find available commands
  :View [split|merged]         Choose layout; no argument toggles
  :Focus staged|unstaged      Select first file/hunk in that group
  :ReviewRefresh              Refresh snapshots and file list
  :ReviewStage hunk|file       Stage selected hunk/file
  :ReviewUnstage hunk|file     Unstage selected hunk/file
  :ReviewComments             Find annotations (same as :Annotations list)
  :Annotations list|next|prev  Find notes / jump to next/previous
  :Annotations new            Create a separate note at the cursor
  :WriteFeedback              Send saved annotations
  :ReviewHarness [name ID]    Show/select CLI or custom receiver
  :ReviewRetry                Retry last immutable delivery
  :ReviewOutbox               Browse payloads and receipts
  :ReviewArchive              Clear round/drafts after confirmation
  :Harness status             Show connection and delivery receipt
  :Harness use amp|claude     Select type; Amp also discovers live sessions
  :Harness install amp        Install bridge and request reload
  :Harness connect [amp]      Discover/select live session
  :Harness list               Search and manage harnesses across worktrees
  :Harness panel              Same panel with live activity
  :Harness rename ID ALIAS     Set a local alias, without renaming the agent thread
  :Harness send [alias]       Choose recipient and compose a general message
  :Harness retry              Retry last delivery, not edited drafts
  :Harness disconnect [alias] Disconnect chosen harness; do not stop the agent
  :Worktree list              Choose a worktree
  :Worktree switch [target]   Switch by branch/path, or choose
  :Worktree new [branch [path]] Create worktree and launch harness

:help {topic} opens native/plugin help. :messages shows errors/notifications.
:qa exits; :qa! also discards unsaved ordinary files. Both lose session-only drafts.
Shell commands (:!) can change files/index outside the editor's protections.

==============================================================================
DRAFTS AND DELIVERY                                            *rediff-drafts*

Accepted/completed delivery deletes sent notes/text but preserves newer edits.
Failed, pending and local-only batches stay in this process. Leaving/re-entering
Review retains drafts; exiting discards them without an unsent-note quit guard.
Every fresh editor starts empty. Submitted payloads/receipts persist in the outbox.

You can keep editing while the agent responds.
One delivery per worktree may be in flight. Typing drafts does not write to disk.
Keep the editor running during delivery. "accepted" means queued; "completed"
means the turn finished, not that its changes are correct. Inspect the session
and receipt before retrying uncertain delivery. Retries use the original payload.
Without a binding, submissions stay local. Credentials never belong in Nix/Git.

Built-in harnesses receive JSON: rules once, then context and annotations/message.
There is no prose prefix or epilogue. Explicit authorization in your feedback
permits the named Git/PR actions; otherwise the agent must ask. Exact ranges and
snapshot status remain. Source/patches stay in the private outbox, referenced by
path; custom receivers get the full payload. Choose your receiver carefully.

LIMITS                                                        *rediff-parity*
Binary files, merge conflicts and files over 2 MiB are unsupported. Notes are
not re-anchored automatically. File/hunk annotation scopes, LSP inspection, blame
and collapsed/compact diffs are not implemented. See FEATURES.md for the inventory.
